# あとろく（atoroku）構想と引き継ぎ

> 仕事中の会話を「録音ボタンを押し忘れても」残せる iPhone + Apple Watch アプリ。押す前の30分をさかのぼって保存し、端末の中で日本語の文字にし、文字だけを Claude に渡して「決まったこと・頼まれたこと・自分の宿題」に整える。音声は iPhone から出さない。
> 2026-10-18 にプロジェクト「作るもの探し」（スレッド「クレジット活用 仕切り直し」）で構想をまとめ、新しいプロジェクトに移すために作った資料。
> 構想メモ（図つき、Claude Doc）: https://claude.ai/code/artifact/51ad07e2-2fd7-4e0b-a808-86ed91868668
> この資料だけで話が通じるよう、構想メモの中身もすべてここに書いてある。

## 2. 背景と動機
- 会議や立ち話は始まってから「これは残したかった」と気づくことが多く、普通のボイスレコーダーは押した瞬間からしか録れない。榊原さんは「押すのを忘れる」のが前提なので、無意識のうちに録れていて、必要なときだけ瞬間的に残せるものが欲しい。
- 録音は会社で問題ないことを確認済み。
- もう一つの動機は、毎月失効している Claude Max 付属の API クレジット（月100ドル）の使い先。要約と整理に Sonnet 5.5 を使っても月に数百円しか使わないので、質を優先した設定にできる。

## 4. 一日の流れ
1. 朝、出社したら Control Center のボタン（またはアクションボタン）をタップする。アプリが開いて「待機中」になる。位置情報で会社に着いたときに「待機を始めますか」の通知を出してもよい。
2. iPhone は直近30分の音声を持ち続ける。画面上部のマイクの印（橙の点）は一日中ついたまま。
3. 「これは残したい」と思ったら Apple Watch の画面を1回タップ。押す前の30分が保存され、録音はそのまま続く。長い会議は「会議モード」で、止めるまで続けて保存する。
4. 保存された音声は、その場で端末の中で日本語の文字になる。音声も端末の中に残る（残す日数は設定）。文字が崩れた箇所はあとで聞き直せる。
5. 夕方、または保存のたびに、文字だけが Claude に送られ、「件名・決まったこと・頼まれたこと・自分の宿題・用語」に整理される。
6. あとから「先週の〇〇さんとの話」を日付や相手で探し、要約と原文（文字起こし）を読める。
7. 退社したら待機を止める。時刻や位置での自動停止もできる。

## 5. しくみ
Watch は合図を送るだけで、マイクと記憶は iPhone が担う。音声は端末の中に残り、Claude には文字だけが渡って要約が返る。

- **iPhone アプリ（Swift / SwiftUI）**: 音声セッションと直近30分のリングバッファ。保存、文字起こし（SpeechAnalyzer）、保管（SwiftData）、検索、Claude への送信。Control Center のボタンとアクションボタンは App Intents で。
- **リングバッファ**: メモリではなく、1分ごとの小さな音声ファイルをストレージに書き、古いものから消す。16kHz モノラルの圧縮音声で1時間約15MB。長さを5分〜半日のどこにしてもバッテリーは変わらず、変わるのは保存後の文字起こし時間だけ。
- **Watch アプリ（watchOS 10）**: 大きなボタンが一つある画面とコンプリケーション。WatchConnectivity の `transferUserInfo` で iPhone に合図を送る（iPhone アプリが裏にいても届く。`sendMessage` は前面が必要）。
- **Claude API**: 利用者自身の API キーを Keychain に保存して直接呼ぶ。サーバーは持たない。
- **文字起こし**: iOS 26 の SpeechAnalyzer / SpeechTranscriber（端末内、日本語対応、長時間向き、モデルのダウンロード不要）。精度が足りなければ WhisperKit（large-v3-turbo 約1.6GB）に切り替えられる構造にする。

## 6. iOS の制約と対応（調べた根拠つき）
| 制約 | 影響 | 対応 |
| --- | --- | --- |
| iOS はバックグラウンドから録音を開始できない（[Apple Developer Forums](https://developer.apple.com/forums/thread/120038)） | 待機開始はアプリが前面にあるときに限る | Control Center のボタン・アクションボタン・通知はどれもアプリを開いてから開始する。開始後は `audio` のバックグラウンドモードで一日続く |
| 通話や他アプリの音で録音が中断する | 録り漏れ | `AVAudioSession` を `playAndRecord` + `mixWithOthers` で持ち、中断終了の通知で再開する（[実装記事](https://blog.risingstack.com/reliable-background-recording-on-ios-watchos/)） |
| Watch アプリ自身の裏での録音は不安定 | Watch をマイクにできない | Watch はボタンだけ。`transferUserInfo` は iPhone アプリが裏にいても届く（[Apple Developer Forums](https://developer.apple.com/forums/thread/766559)） |
| 端末内の文字起こしは iOS 26 が必要 | iPhone 11 以降に限る | iPhone 16 なので問題なし（[SpeechAnalyzer 解説](https://blog.addpipe.com/apple-speechanalyzer-api/)、[WhisperKit との比較](https://www.forasoft.com/blog/article/speech-recognition-with-neural-networks-on-ios-1621)） |
| Apple Watch Series 5 は watchOS 10 が最後 | 新しい watchOS の API は使えない | Watch 側は watchOS 10 を対象にし、WatchConnectivity とボタン画面だけにする |
| マイク使用中の表示（橙の点） | 一日中つく | 仕様として受け入れる。周囲への説明にも使える |

- **待機中の他の操作への影響**: 動画・音楽の再生、画面操作、他アプリは普通に使える（`mixWithOthers`）。マイクを使う操作（通話、動画撮影、ボイスメモ、Siri）の間だけ録音が止まり、終わると再開する。通話の中身は iOS の仕様で残せない。
- **Bluetooth イヤホン**: イヤホンのマイクを使う設定にすると通話用の低音質モード（HFP）に切り替わり、音楽や動画の音がこもる。マイクは iPhone 本体に固定し、イヤホンは再生専用（A2DP）にする。
- **騒がしい場所での精度**: 文字起こしは雑音で「ゼロになる」のではなく「ところどころ崩れる」。英語の[ベンチマーク](https://www.gigazine.net/gsc_news/en/20260714-apple-speech-analyzer-benchmark/)では SpeechAnalyzer の誤り率はきれいな音声で 2.1%、雑音の多い音源で 4.6%（Whisper Small より低い。日本語は未計測）。雑音より効くのは距離と置き場所で、ポケットや鞄の中ではこもって大きく落ちるため、会議中は机に置く前提。端末内の文字起こしは[話者分離を持たない](https://rohitraj.tech/en/notes/apple-speechanalyzer-vs-whisper-on-device-stt-2026)ので複数人が被ると一本の文になる。iPhone の「声を分離」は[アプリから直接は選べない](https://developer.apple.com/forums/thread/844448)。対策: 音声を端末内に残して聞き直せるようにする、Claude には不明な箇所に「？」を付けて作文させず話者は文脈から推定させる、段階0の計測にポケット・机・騒がしい部屋の比較を入れる。
- **バッテリー**: 未計測。一晩録音して解析するアプリの例では 10〜14% という自己申告（[作者の記事](https://dev.to/sleeptrace/how-to-process-8-hours-of-audio-on-an-iphone-without-draining-the-battery-ab9)）。段階0で実機で測る。

## 7. Claude の使い方と費用
Claude の仕事は「文字起こしをあとから使える形に整える」だけ。文字起こしは端末内で無料。Claude API は音声入力を持たないので、文字起こしを端末側で行うのは必然でもある。

- **入力と出力**: 保存した1件（30分でおよそ1万字）の文字起こしを送り、構造化出力（JSON）で受け取る: 件名（1行）と要旨（3行以内）／決まったこと／頼まれたこと（誰から、期限）／自分の宿題／出てきた用語・固有名詞（誤変換を直す材料にもなる）／各項目が文字起こしのどこから来たか（時刻）。不明な箇所は「？」を付け、作文しない。話者は文脈から「おそらく〇〇さん」と推定させる。
- **モデル**: 日々の整理は Sonnet 5.5。タグ付けやちょっとした言い換えは Haiku 5.5。モデル名は設定で変えられるようにする。
- **費用**（[Anthropic の料金](https://docs.claude.com/en/docs/about-claude/pricing)。Sonnet 5.5 は入力100万トークン $2・出力 $10、Haiku 5.5 は $0.10・$0.50）

| 前提 | 1日 | 月（20日） |
| --- | --- | --- |
| 1日に保存する会話が合計3時間（約6万字、6〜9万トークン）を Sonnet 5.5 で整理 | 約 $0.15（約20円） | 約 $3（約450円） |
| 同じ量を Haiku 5.5 で | 約 $0.01 | 約 $0.2 |

- 月100ドルのクレジットの数%しか使わないので、残りで「今週の振り返り」「この人とのやりとりの経緯」のような複数日をまたぐ整理も足せる。
- 日本語のトークン数は文字数の1〜1.5倍として見積もっている。Haiku 5.5 は1回の入力が10万トークンを超えると単価が上がるので、保存した1件ごとに送る。

## 8. プライバシーと安全
- 音声は一度も iPhone の外に出さない。クラウドに上がるのは文字だけで、それも利用者自身の API キーで Anthropic に直接送る。途中に自分たちのサーバーは置かない。
- 音声は端末内に一定期間残す（初期値30日、固定した録音は消さない）。文字起こしと要約の保存期間も設定できる（たとえば90日）。リングバッファは1分ごとのファイルで常に上書きされ、待機を止めれば消える。
- アプリの中身は Face ID で保護。API キーは Keychain。バックアップは利用者が明示的に Markdown で書き出したときだけ（無料の Apple ID では iCloud が使えないこともあり、自動同期しない）。
- iOS が出すマイクの印は消さない。残すと決めたときに相手に一言伝える、を使い方の注意として書く。
- Anthropic 側: API 経由の入力は商用利用条件ではモデルの学習に使われないとされている。公開前に最新の条件を確認して README に書く。
- 法的な注意: 日本では自分が参加する会話の録音は原則として違法ではないが、会社が録音を禁じている場合に懲戒が有効とされた判例がある（[甲社事件・東京地裁立川支部 平30.3.28](https://www.rodo.co.jp/precedent/66290/)）。榊原さんの会社は問題なしと確認済み。公開する場合は README に「勤務先のルールを確認すること」を書く。

## 9. 既存との違い
「さかのぼり録音 × 端末内で日本語文字起こし × 自分の API キーで要約 × 音声を外に出さない」を全部満たすものは、調べた範囲ではなかった（2026-10-18 時点）。

| 製品 | さかのぼり | 文字起こし | 要約 | 音声の行き先 | 費用 |
| --- | --- | --- | --- | --- | --- |
| [AudioBuffer](https://apps.apple.com/us/app/audiobuffer/id6761793483)、Heard、Rewind Recorder、RetroCord（iPhone） | あり | なし | なし | 端末内 | 無料〜買い切り |
| [Backtrack](https://apps.apple.com/app/id1477089520)（Mac） | あり（最大5時間） | なし | なし | 端末内 | 有料 |
| [Limitless Pendant](https://jp.plaud.ai/blogs/blog/plaud-notepin-s-vs-limitless-pendant) | 常時録音 | クラウド | クラウド | クラウド | 本体＋月額 |
| [PLAUD NotePin](https://jp.plaud.ai/blogs/blog/plaud-notepin-s-vs-limitless-pendant) | なし（押して録音） | クラウド | クラウド | クラウド | 本体＋月額 |
| [Auday](https://hashout.jp/gadget/12040/)（Apple Watch） | 不明 | あり（日本語非対応） | あり | 不明 | 買い切り1,500円 |
| **あとろく** | あり（30分、可変） | 端末内・日本語 | 自分の Claude キー | 端末内のみ（一定期間残す） | API 代のみ（月数百円） |

競合が弱い理由は、クラウドで文字起こしする製品は月額で元を取る必要があり「自分の API キーで動かす」設計を選びにくいから。個人開発の OSS ならその制約がない。

## 10. MVP と段階
最初に試すのは「iPhone で一日録り続けられるか」。これが駄目なら設計を変えるので、文字起こしより前に確かめる。段階3を終えた時点で、榊原さん自身が毎日使うかを判断して続けるか決める。

| 段階 | 作るもの | 確かめること |
| --- | --- | --- |
| 0. 計測 | リングバッファで録り続けるだけのアプリ | 裏に回して8時間止まらないか。通話のあと再開するか。バッテリーが1日で何%減るか。同じ会話をポケット・机・騒がしい部屋でどれだけ拾えるか |
| 1. iPhone 単体 | 待機の開始・停止、アプリ内の「残す」ボタン、保存ファイルの一覧と再生 | 押す前の30分が欠けずに残るか |
| 2. 文字起こし | SpeechAnalyzer で日本語に。失敗したらあとでやり直す。文字と音声の時刻を対応づけ、崩れた箇所を聞き直せる画面 | 実際の会話で読める精度か。距離・複数人・雑音でどこまで落ちるか。WhisperKit と比べる |
| 3. Claude | 要約のプロンプトと構造化出力、一覧と検索、API キー設定 | 1週間使って「宿題の拾い漏れが減ったか」。ここで毎日使う気になるかが決まる |
| 4. 入口 | Control Center のボタンとアクションボタン（App Intents）、出社時の通知 | 朝の待機開始を忘れなくなるか |
| 5. Watch | ボタン一つの画面とコンプリケーション、`transferUserInfo` | Series 5（watchOS 10）で届くか。iPhone が裏にいても保存されるか。届くまでの時間 |
| 6. 磨き | 会議モード、Markdown 書き出し（Obsidian など）、話者の区別、時刻・位置での自動停止 | 他の人に渡せるか。渡すならここで App Store（年99ドル）を決める |

## 13. 新しいプロジェクトでの最初の一歩（段階0 の具体手順）
1. リポジトリ `ishibashi0112/atoroku` に README・CLAUDE.md・docs/concept.md（この資料の内容）を入れる。CLAUDE.md の絶対ルール: 音声は端末の外に出さない、Claude に渡すのは文字だけ、サーバーを持たない、無料 Apple ID で動く範囲で作る。
2. Remote Control で榊原さんの Mac に入り、Xcode 26 と `xcrun devicectl list devices` で iPhone 16 が見えることを確認する。
3. Xcode で iOS アプリ `Atoroku` を作る（SwiftUI、Personal Team で署名、Bundle ID は `com.<name>.atoroku`）。Signing & Capabilities で Background Modes の「Audio, AirPlay, and Picture in Picture」を有効にし、Info.plist に `NSMicrophoneUsageDescription` を書く。
4. 録音の芯を作る: `AVAudioSession` を `.playAndRecord` + `.mixWithOthers`（`.allowBluetoothA2DP` は付け、HFP は付けない）で有効化し、`AVAudioEngine` の入力を1分ごとに `AVAudioFile`（AAC、16kHz モノラル）へ切り替えて書く。古いファイルを消して設定時間分だけ残す。中断（`AVAudioSession.interruptionNotification`）とルート変更で再開する。
5. 画面は「開始」「停止」「今の状態（経過時間、ファイル数、残容量）」だけ。保存ボタンはまだ要らない。
6. 計測を1日行う: 朝に前面で開始 → ポケットで8時間 → 夕方にバッテリーの減り、止まった時刻（あれば）、通話後の再開を記録する。別に、同じ会話をポケット・机・騒がしい部屋で録って聞き比べる。
7. 7日目に `xcodebuild` + `devicectl install` の再インストールを1本のスクリプトにする。
8. 結果を docs/stage0.md に書き、段階1へ進むか設計を変えるかを決める。
